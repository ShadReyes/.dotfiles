# Font access and licensing in reconstruction reviews

Identify access when shortlisting a font, before asking the user to approve its appearance. Keep these findings visible beside the comparison, not only in a machine-readable handoff or final packaging notes.

## Research and record

For each lettering element, record:

- Exact family, style, version when known, foundry, and visual-match status.
- Representation used: licensed local font rendering, vendor raster preview, or custom curves. A preview does not establish access to font software.
- Access status: open-license files retained, commercial license evidenced, purchase required, or unknown. Installation alone does not establish a license; absent local evidence does not prove the user has never purchased it.
- Official purchase URL, exact styles included, current displayed price/currency, seat assumptions, and check date. Label starting prices and quote-only costs. Verify bundle contents; similar names or adjacent weights are not equivalent.
- License source/version and applicable use: finished physical products, fixed outlined digital output, internal personalization, customer-facing editors, server/app embedding, redistribution, and outline or font modifications, as relevant to the requested workflow. Separate modifying font software from altering artwork outlines; identify ambiguous clauses instead of asserting either permission or prohibition without support.
- Required action, evidence of purchase or permission when available, and outstanding coverage questions. Keep receipts and personal account details outside public deliverables.

Read the current license from the intended seller. A foundry-direct license and a reseller license can differ. Cite the applicable terms and distinguish explicit clauses from an inference about the workflow. Ask the foundry a precise question when coverage remains unclear; prepare the inquiry for the user, but sending it requires authorization. A desktop purchase does not by itself establish server or customer-editor permission.

## Present the decision

Include a compact table in the visual review: element; exact font/style; current access and preview representation; purchase source and cost; coverage or action remaining. Include open-license fonts too, naming the license and retained files. State whether the displayed design can already be reproduced from usable font files.

Offer the actual available routes when relevant: supply existing licensed files, acquire the exact styles and suitable license, or review an alternative font with suitable terms. Show the fidelity effect of an alternative. Custom tracing or converting text to curves is not a substitute for checking applicable rights.

Record visual approval, spending authorization, license acquisition, and production verification separately. Visual approval does not authorize a purchase or establish license coverage. Keep approved visual work intact while resolving access. Before production use or packaging, verify usable files and coverage for that use; include font software in deliverables only when redistribution is permitted.

## Handoff

Save the per-font access records and dated source links in `font-match.json`; link the same summary from the HTML brief and `launch.json` when present. Retain file hashes and relevant license evidence. The independent reviewer checks that each selected lettering style has a visible access entry and that preview-only work is not presented as production-ready. Revisit coverage when the renderer, distribution method, personalization access, or font modifications change.
